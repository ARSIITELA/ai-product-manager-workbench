# 项目案例分享：产品经理个人工作台

AI 产品经理的日常，总在写 PRD、竞品分析、提示词方案和评估报告之间来回切换，重复交代项目背景更是家常便饭。作者干脆自己搭了一个 AI 工作台，把立项、PRD、评估、版本规划等六个入口装进同一个项目空间，让上下文能复用、文档能接着改。本文完整拆解这个工作台的设计思路与使用流程，并分享从界面到协作的踩坑心得。

这阵子在折腾一个AI 产品经理工作台。

可以把立项报告、PRD、竞品分析放进去，还有提示词方案、效果评估和版本规划。做 AI 产品总要写这些，我就想干脆放到一起吧。写完接着改，改完还能找得到，省点来回翻东西的功夫。

用 AI 帮忙写初稿已经挺方便了。可你拿着它去评审，人家问你给谁用、这版做多大、为什么要加这个需求，还是得你来回答。总不能说“AI 是这么写的，所以我就这么做了”。

## 撰写 PRD 功能

比如要做一个知识问答助手，你让它写 PRD，提问、检索、生成回答这些功能都能先列出来。

到了评审大家就要接着问了。资料没找到呢？引用错了呢？用户怎么知道这段话根据什么写的？什么什么的这些，并且跟各部门对接的留存记录也需要有地方能帮你调出来。

这些得写到设计和研发看了能接着干活的程度，文档写完后要聊的东西还多着呢。

所以我在 PRD 的任务要求里放了用户流程、AI 的输入输出、失败处理、权限和验收标准。初稿出来后一起看看哪条没说清楚，再接着改。

立项报告也差不多，要写清楚解决什么问题、谁有这个问题、有没有证据、AI 在这里能做什么、准备花多少资源。手里有多少材料就先按这些写，没确认的写“待补”。

不知道的地方先留着。

工作台会要求助手把事实、假设和建议分开写，尽量说清楚哪些已经知道、哪些只是猜的。模型也可能分不准，读到一个结论时还是得回头找找依据。

竞品分析里的功能、价格和商业模式也要查过以后再拿来聊，来源和日期一起写上。人家有这个功能，我们是不是也要做？这事还得看我们的用户用不用得上。

## 换任务时不从头介绍项目

立项里刚说完第一版给内部客服用，写 PRD 时又得讲一遍，写提示词时还得讲。讲到后面漏掉两句都不奇怪。

我就想让之前确认过的内容下次还能接着用。

AIPM Lab 现在把东西按项目放。你可以新建一个项目，把最初的想法写进去，后面的对话和文档都放在里面。下个任务的要求里会让助手先看看项目里已经有哪些文件，再结合你新给的材料写。

首页有“我的项目”和“最近文档”，想接着改 PRD 点进去就行。东西多了以后也能搜文件和之前的对话，也能少翻几遍。

选好任务和项目后把材料放进去，再点“开始创作”，整理好的要求会先出现在对话输入框。你可以看一遍，想补什么再补上，然后自己发送。

有时候看着这段话才想起自己还没说预算，也没加上“第一版只做只读问答”“先给内部人员用”这些限制。不然助手往下写就可能写大了。

用起来大概这样：

选任务和项目 → 放材料 → 补完要求再发 → 聊初稿 → 看过以后保存。

## 我把方案和评估放在一起出

我想把提示词方案和效果评估放到一起用。

提示词方案会帮忙整理角色、任务、输入、限制和输出格式，也会准备示例，写清出问题时怎么处理。需要从业务里接进来的信息就用变量留好位置，后面再接。

用的时候发现回答太长、没按要求引用资料，或者明明不确定还在往下答，就把这些问题带回来接着改提示词。也得看看给它的材料是不是有问题，别忙活半天改错地方了。

评估方案先帮忙把怎么测写出来，包括拿什么样本测、怎么打分、引用查到哪一步、没答案时怎么处理才合适。回答要等多久、一次花多少钱也得算进去。

演示时答得挺好，换几个问题、换一批资料可能就开始出状况了。别人真要天天用总得多测几种情况。

这个入口现在帮忙写评估方案和待填的结果表，结果得拿样本测完再填

看模型写一句“效果优秀”就准备上线，多少有点草率。让它自己写结论再夸自己优秀，这个成绩也太好拿了。还是得看看拿什么测的、哪儿过了、哪儿没过，再判断哪些问题能接受、哪些得先改好。

版本规划也会用到这些信息，要写清楚哪些先放进 MVP、哪些晚点做、为什么这么排、要等谁或等什么条件。还没确定谁做、什么时候能做就先留着，把前提说清楚。

我也希望下一版全做完，排期的时候还得想想谁来干。

这六个入口都能单独用，手里已经有 PRD 就直接做评估方案。测完觉得范围不对再回去改立项和 PRD 也行，看眼下要做什么，不用按顺序挨个点一遍。

## 写完了还得接着改

文件名叫“最终版”也不耽误它明天接着改，后面还能排上“最终版2”“这次真的最终版”等好几个版本。

保存前工作台会先给你看预览。改已有文档时也能看看前后差在哪，看完后自己确认保存。

范围和验收标准这两处我会多看几眼。有些句子就改了几个字，意思可能已经变了。先把这版做什么、做到哪一步算完看清楚，后面跟人聊的时候也有数。

读到有疑问的话可以引用到项目对话里接着问。窗口宽的时候文档和对话能并排放，想从头仔细读一遍就打开专注阅读。

文件现在放在电脑上的项目文件夹里，主要是 Markdown 和文本文件，能复制、下载，也能看 Markdown 原文。暂时不用的扔进回收站，哪天又要了还能找回来。

做产品总要翻之前的材料、改需求、重新讨论。下次打开要是还得找半天文件，又看不清刚改过什么，实在有点劝退。存东西和找东西这几步得顺手。

## 按自己的喜好更改下界面吧

毕竟是私人工作台，界面、画风等就可以张狂一点了，我个人更加喜欢页面跟Logo适配，我想让页面跟它搭起来，圆润点、颜色温和点，看着舒服些。

现在用了偏暖的底色和一点绿色，导航、任务、项目和最近文档的位置也重新摆过，打开后先能找到今天要干的事。你可以自己调发送快捷键，也能选择要不要记住上次进度、要不要减少动态效果。

好不好用还得拿项目进去做一段时间。有些地方要来回点，有些内容读着费劲，这些问题光做界面的时候还真不一定能发现。

APM Lab 还在开发。现在六类入口会准备不同的任务要求，后面通过项目对话和助手写初稿，最后写成什么样跟你给了多少材料、用了什么模型都有关系。

接下来想多拿几个项目试试，看看哪些文档还得大段重写、哪些背景总要补、存东西和找东西方不方便。先用一轮再决定改哪儿。
